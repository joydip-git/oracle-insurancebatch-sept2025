JavaScript Object Notation/XML 

Consumer -> the one who uses/consumes the service

Provider -> the one who provides a service

Consumer and Provider can exchange data in platform/technology neutral manner
such as via JSON or XML format etc.

Consumer will convert their technology/language specific data into JSON/XML format -> Serialization
Provider after receiving the request (via web server) and fetching that JSON/XML data, will convert it into its language specific format -> Deserialization

Consumer and Provider will communicate via similar protocol as decided by Provider
Consumer and Provider will communicate via a standard neutral data exchange format as decided by Provider
Provider will also decide on the security feature for request/response

Protocols:
	HTTP - stateless and connectionless, provide no security to the data
	TCP - stateful and connection full, provide security to the data

Eclipse Jersey: Jersey is the reference implementation of Jakarta RESTful Web Services (JAX-RS). It provides a robust and full-featured framework for building RESTful web services within the Jakarta EE ecosystem.

RestEasy:
It is a Java framework, a portable implementation of the Jakarta RESTful Web Services (JAX-RS) specification, for developing client and server RESTful web applications and services.
It provides annotation-driven support for creating REST APIs and can run in any standard Java Servlet container like WildFly, Tomcat, or Jetty. 
RESTEasy also includes client-side functionality to invoke remote web services using JAX-RS annotations and offers integration with other frameworks like Spring Boot.  

Servlet:
------------------
Simply put, a Servlet is a class that handles requests, processes them and reply back with a response.

For example, we can use a Servlet to collect input from a user through an HTML form, query records from a database, and create web pages dynamically.

Servlets are under the control of another Java application called a Servlet Container. When an application running in a web server receives a request, the Server hands the request to the Servlet Container – which in turn passes it to the target Servlet.
