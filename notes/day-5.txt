Inner/nested classes:
------------------------------
	you want to logically group classes and interfaces in one place 
	for more readability
	for maintainability
	less code for writing (code optimization)
exception handling

types of nested class:
	a. member nested class: a class inside a class/interface
		I. non-static member nested class
		Note: the non-static nested member class has access to all the members of the outer class (both static and non-static)
		II. static member nested class
		Note: the static member inner class can access ONLY static member of the outer class

	b. local nested class: a class inside a method
	Note: 
	1. local inner class can't be static, since anything local of a method can't be declared with "static" keyword, as static keyword is used with members of the class
	2. local inner class has access to the local data of the method, where it has been declared

	c. anonymous inner class: a class which is a nested class, whose name is decided by Java compiler and generally that class is used to provide an implementation of the interface/abstract class members

class inside an interface
--------------------------------
interface Calculator{
	int calculate(int a, int b);

	class Implmentation implements Calculator{
		@Override
		public int calculate(int a, int b){
			return a+b;
		}
	}
}

You do not want to use the inner class of the interface with default implementation of calculate method

solution:
1. create you own class and implement the interface and the method(s)
2. use anonymous type

//anonymous type
static void main(String[] args){

	Calculator subtractor = new Calculator() {
            @Override
            public int calculate(int a, int b) {
                return a - b;
            }
            
        };
}

equivalent to the following code:
--------------------------------------
the java compiler creates a locally nested/inner class with some name, when it compiles the Java source code to byte code

App.java
static void main(String[] args){

    //javac decides the name of the local inner class inside the main method
    class App$1 implements Calculator {
        @Override
        public int calculate(int a, int b) {
            return a - b;
        }
    }
    Calculator subtractor = new Calculator.App$1();
}

actually the anonymous local inner class will be inside a separate file (when byte code is created) but will be considered as inner class of the method, which is coped within the method where it is created
--------------------------------------------------------------------------------
file name: App$1.class (from App.java)
code:

            return a - b;
        }
    }

file name: App.class (from App.java)

Pure/stateless function:
------------------------------
	such a function which does not alter/mutate/change the input data, but performs some operation on the input data to produce an different output every time exactly in the same way, with no side effects, i.e., modifying external data or performing I/O


public int add(int a, int b){
	return a + b;
}

Functional Programming:
-----------------------------
Functional programming is a programming paradigm that focuses on creating code by applying and composing pure, stateless functions, treating computation as the evaluation of mathematical functions rather than executing a sequence of imperative commands. It emphasizes immutability (non-changing data), declarative code ("what to solve" rather than "how"), and avoids shared state and side effects, leading to more predictable, testable, and parallelizable code. 

Stream API
-------------------------
It enables declarative operations on data, allowing developers to focus on what to achieve rather than how to iterate. 
They are wrappers around a data source, facilitating operations without modifying the original data.
Streams support operations like sorted, filter, map, and reduce, promoting a functional programming style.
Operations can be chained together to form a pipeline, which is optimized for efficient processing.
Stream<T> API methods (such as sorted, filter, map, reduce etc.) accepts a reference of class instance which implements certain interface. Through those instances you provide the logic to be applied on the every element of that stream of data.

such as, 
sorted() method accepts instance of a class implementing Comparator<T> interface
filter() method accepts instance of a class implementing Predicate<T> interface
forEach() method accepts instance of a class implementing Consumer<T> interface

Some of the Stream API methods terminate the stream, such as toList(), forEcah() etc.

Callback mechanism:
----------------------------
	passing a reference of a method to another method so that, the former can be called from later 

void foo(){}

void invoker(FI fi){}

void main(){
	invoker(foo);
}


Method Reference
-------------------
	a reference to a method
	we use a functional interface to store reference to a method
	you can call the method using the reference to the method
	
Functional Interface:
-----------------------------
	an interface with exactly ONE abstract method (but can have many default methods - methods with code, not abstract)
	- Comparator<T> => int compare(T o1, T o2);
	- Predicate<T> => boolean test(T t);
	- Consumer<T> => void accept(T t);
	Functional interface can be declared with @FunctionalInterface annotation (without that also its fine)	

Lambda expression
--------------------
	a concise syntax to write anonymous inner class code and method reference
	Calculator<Integer> addFn = (a,b) -> a+b;
