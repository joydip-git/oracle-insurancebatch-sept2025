abstract method
	a method which has no code (implementation), just declaration
	an abstract method/getter/setter must be declared with abstract keyword
	
	- public abstract String printInfo();
	- public abstract String getName();
	- public abstract void setName(String name);


abstract class
	it is a class with at least one abstract method/getter/setter
	the class having an abstract member must be declared with abstract keyword
	an instance of an abstract class can not be created
	an abstract class can have explicit constructors, data members, other non-abstract methods/getter/setter
	any class (child) inheriting from an abstract base class MUST override/implement the abstract methods/getters/setters. otherwise that child class also becomes an abstract class and has to be declared with an abstract keyword.
	a child class can't inherit from more than one abstract class

Employee -> 
	void calculateSalary(){} 
Developer -> 
	@override 
	void calculateSalary(){}

abstract class can be used like a base template with abstract methods, that must be implemented in their own way in every child class

in you s/w, if you have many classes of similar nature and you want them to have common methods as well common data members, but some of the methods have no implementation, rather child classes should provide different implementation, then to make it sure the classes follow the expectation, you can create an abstract class with those abstract methods and make the child classes inherit them.


interface:
	a pure abstract class
	it can have ONLY abstract methods/getters/setters
	an interface can't have any explicit constructors, data members, other non-abstract methods/getter/setter (except default methods)
	declare an interface with "interface" keyword
	no need to use abstract keyword separately with either interface or its abstract members, since they are by default abstract
	an instance of an interface can not be created	
	any class (child) implementing (inheriting) an interface, MUST override/implement the abstract methods/getters/setters. otherwise that child class also becomes an abstract class and has to be declared with an abstract keyword.
	an interface can be inherited into another interface
	a class can implement more than one interface

in you s/w, if you have many classes of similar nature and you want them to have ONLY common methods with different implementation, but no common data members, then to make it sure the classes follow the expectation, you can create an interface with ONLY those abstract methods and make the child classes implement them.

final keyword:
-------------------------
when used with class -> the class can't be inherited

when used with method -> the method can't be overridden

when used with data member -> makes the data member as "read-only", which should be assigned either immediately (while declaring) or by constructor ONLY. No other method can be used to initialize that "read-only" data member. But, if this data member already is assigned a value while declaring, then even constructor can't be used to assign value to it.

when used with data member along with static keyword -> it makes data member "constant", whose value can ONLY be assigned when declared and can't be changed any further

when used with local variable -> it mnakes the local variable of the method "constant", whose value once assigned can't be changed
	
Object:
--------------
Class<?> getClass(); [this is a final method and can't be overidden in child class]

these following methods can be overriden in child class:
int hashCode();
boolean equals(Object obj);
String toString();


JVM has Class loader, whose job is to load metadata (information) of any class in the runtime, before it can be used, such as before creating instance etc.

Instances of the class "Class" represent classes and interfaces in a running Java application
Class<T> -> Class loader of JVM loads definition/information/metadata of any  data type(class/interface) from the byte code and stores that information in inside an instance of class "Class", created by runtime (JVM itself)

Class<B> => instance of Class storing information of B class
